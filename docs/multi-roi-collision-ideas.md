# 다중 ROI 동시 점유 처리 방안

> 흰 지팡이가 두 개 이상의 ROI에 동시에 걸쳤을 때 어떤 안내를 어떤 순서로 발화할지에 대한 설계 아이디어 모음

---

## 현재 동작 (기준선)

```
지팡이 1 → ROI A (priority 1)  →  A 트리거
지팡이 2 → ROI B (priority 2)  →  B 트리거  (동시 발화 가능)
```

- 각 ROI가 독립적으로 디바운스/쿨다운 판정
- 같은 ROI에 지팡이 2개가 동시에 들어와도 1번만 발화 (쿨다운 보호)
- 서로 다른 ROI에 들어오면 **두 음성이 겹쳐 재생**될 수 있음

---

## 아이디어 1 — 우선순위 선착 (Priority First-Come)

**개념**: ROI에 설정된 `priority` 숫자가 낮은 쪽이 항상 이긴다.  
같은 프레임에 여러 ROI가 동시에 트리거 조건을 충족해도 **가장 높은 우선순위 1개만 발화**.

```
ROI A (priority 1) + ROI B (priority 2) 동시 충족
→ ROI A만 발화, ROI B는 이번 사이클 무시
→ ROI B의 디바운스 타이머는 유지 (지팡이가 ROI B 안에 있는 한 계속 카운트)
```

**장점**
- 구현 단순 (트리거 목록 정렬 후 첫 번째만 실행)
- 예측 가능한 동작

**단점**
- 낮은 우선순위 ROI는 영구적으로 묻힐 수 있음
- 두 ROI가 모두 중요한 경우 정보 손실

---

## 아이디어 2 — 순차 큐 (Sequential Queue)

**개념**: 동시에 여러 ROI가 트리거되면 **큐에 순서대로 쌓아** 하나씩 재생.  
앞 음성이 끝나면 다음 음성 재생.

```
ROI A, ROI B 동시 트리거
→ 큐: [A 안내, B 안내]
→ A 재생 → 완료 → B 재생
```

**장점**
- 모든 안내를 다 전달할 수 있음
- 정보 손실 없음

**단점**
- 음성 파일 길이에 따라 큐가 길어질 수 있음
- 긴 큐는 오히려 혼란 (이미 지나친 ROI 안내가 뒤늦게 나올 수 있음)
- 음성 재생 완료 이벤트 감지 로직 필요

**개선안**: 큐 최대 길이 제한 (예: 2개), 오래된 항목 자동 폐기

---

## 아이디어 3 — 쿨다운 공유 (Global Cooldown)

**개념**: 어느 ROI든 **하나가 발화하면 전체 ROI에 짧은 공통 쿨다운** 적용.  
개별 쿨다운과는 별도로 글로벌 락을 추가.

```
ROI A 발화 → 전체 글로벌 쿨다운 3초 시작
→ 3초 동안은 ROI B, C 포함 어떤 ROI도 발화 불가
→ 3초 후 각자 쿨다운 기준으로 다시 판정
```

**장점**
- 음성 겹침 방지 가장 간단한 방법
- 기존 코드 최소 수정

**단점**
- 연속 구간(예: 복도 → 계단)에서 두 번째 안내가 지연될 수 있음

**파라미터**: 글로벌 쿨다운 = 평균 음성 길이 + 여유 0.5초

---

## 아이디어 4 — 교차 면적 비율 (Intersection Area Ratio)

**개념**: 단순 교차 여부 대신 **ROI와 감지 구간의 겹치는 면적 비율**로 가중치를 계산.  
가중치가 높은 ROI를 선택하거나 임계값 이상일 때만 트리거.

```
지팡이 하단 strip ∩ ROI A = 70%
지팡이 하단 strip ∩ ROI B = 20%
→ ROI A만 트리거 (비율 50% 이상 기준)
```

**장점**
- "살짝 걸친" 오탐 방지
- 물리적으로 더 의미 있는 판정

**단점**
- Shapely 면적 계산 추가 → 프레임당 연산 증가 (미미하지만 Pi 환경 고려)
- 임계값 튜닝 필요

---

## 아이디어 5 — 방향성 기반 우선순위 (Direction-Aware)

**개념**: 지팡이가 이동하는 **방향**을 보고, 진입 중인 ROI에만 반응.  
이미 통과한 ROI나 멀어지고 있는 ROI는 무시.

```
지팡이 이동 방향 → ROI A (진입 중) + ROI B (이탈 중)
→ ROI A만 트리거
```

**구현 방법**
- N프레임 이전 bbox 중심과 현재 중심을 비교해 이동 벡터 계산
- 이동 벡터와 ROI 중심 방향의 내적이 양수인 ROI만 트리거 대상

**장점**
- 가장 의미론적으로 올바른 방법
- 이미 안내한 구간을 되돌아갈 때 재발화 방지 효과도 있음

**단점**
- 지팡이가 느리거나 정지한 경우 방향 벡터 계산 불안정
- 구현 복잡도 높음, SORT 트래킹과 연동 필요

---

## 아이디어 6 — TTS 인터럽트 모드

**개념**: 높은 우선순위 ROI 트리거가 오면 현재 재생 중인 음성을 **즉시 중단**하고 새 안내 발화.

```
ROI B (priority 2) 재생 중 → ROI A (priority 1) 트리거
→ B 즉시 중단 → A 발화
```

**장점**
- 긴급 상황(예: 계단 진입)에서 중요 안내 우선 보장

**단점**
- 음성이 잘려 사용자 혼란 가능
- priority 설계가 중요해짐

---

## 비교 요약

| 방안 | 구현 난이도 | 정보 손실 | 음성 겹침 방지 | Pi 적합도 |
|------|------------|----------|---------------|----------|
| 1. 우선순위 선착 | ⭐ 낮음 | 있음 | ✅ | ✅ |
| 2. 순차 큐 | ⭐⭐ 중간 | 없음 | ✅ | ✅ |
| 3. 글로벌 쿨다운 | ⭐ 낮음 | 일부 있음 | ✅ | ✅ |
| 4. 교차 면적 비율 | ⭐⭐ 중간 | 없음 | 부분적 | ⚠️ 연산 |
| 5. 방향성 기반 | ⭐⭐⭐ 높음 | 없음 | ✅ | ⚠️ 복잡 |
| 6. TTS 인터럽트 | ⭐⭐ 중간 | 있음(의도적) | ✅ | ✅ |

## 추천 조합

**단기 (지금 당장 적용 가능)**  
→ **아이디어 3 (글로벌 쿨다운)** + **아이디어 1 (우선순위 선착)**  
구현이 간단하고 음성 겹침을 막을 수 있음.

**중기 (안정화 후)**  
→ **아이디어 2 (순차 큐, 최대 2개 제한)** + **아이디어 4 (교차 면적 임계값)**  
정보 손실 없이 자연스러운 안내 순서 제공.

**장기 (고도화)**  
→ **아이디어 5 (방향성)** 추가하여 진입 방향 기반 스마트 트리거.
