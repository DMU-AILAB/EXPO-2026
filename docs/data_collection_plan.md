# 실내 데이터 촬영 계획

> ## ★ 최우선 (2026-09-20 측정으로 확정)
>
> **고정 카메라 · 부감 · 중거리에서 지팡이 사용자를 찍는 클립**을 가장 먼저 확보할 것.
>
> 현재 데이터셋에는 **그 조합이 0장**이다. 배포와 같은 프레이밍의 이미지(`pedcctv`
> 2,753장, train의 27.6%)는 전부 **지팡이 라벨이 없고**, 모델은 "이 프레이밍에는
> 지팡이가 없다"를 그만큼 학습한다. 이것이 배포 임계값에서만 성능이 무너지는 원인
> (conf 0.55에서 28.9% vs 0.25에서 75.8%)이라는 것이 **3관측 실험으로 확증됐다**
> (`model_evaluation_report_v3.md` §15-2: pedcctv를 덜어내면 배포 지점 보존율이
> 23.1% → 34.3%, 쌍별 8-9).
>
> **네거티브를 빼는 방식으로는 못 고친다** — 같은 이미지가 배포 각도의 person 표현
> 이기도 해서, 빼면 실내 탐지(2-9)와 person recall(2-9)이 함께 무너진다(§15-3).
> **양성을 채우는 것만이 처방이다.**


> **목적**: 실내 도메인 갭(`docs/model_evaluation_report_v3.md` §6)을 닫고, 지금
> 검증이 막혀 있는 두 과제(다인 상황, 겹침 대응안)를 동시에 여는 촬영 한 번을 설계한다.
>
> **작성**: 2026-09-19 · **수행 전 §1의 코드 준비 2건을 반드시 먼저 끝낼 것**

## 0. 왜 촬영이 필요한가 — 측정된 근거

| 사실 | 수치 | 출처 |
|---|---|---|
| 실내에서 모델이 거의 동작하지 않는다 | 배포 임계값(conf 0.55)에서 test4 탐지율 **2.8%** (실외 test1은 75.8%) | §11-2 |
| 해상도 문제가 아니다 | imgsz를 320 → 960으로 3배 올려도 실내는 10~20%에 그친다 | §6 |
| 학습 데이터에 실내가 **0장**이다 | train 9,971장 전부 실외/AIHub | — |
| 자세가 치우쳐 있다 | 지팡이 박스 6,767개 중 **눕힘 57.6% / 수직 15.6%** | §12-3 |
| 합성으로는 안 된다 | 회전 증강(`degrees=10`)을 넣자 실영상 탐지가 617 → **173**으로 악화 | §3-1 |
| 다인 검증이 아예 불가능하다 | 평가 영상 4개 **전부 지팡이 사용자 1명** | §9-4, §11-5, §12-6 |

**촬영 말고 다른 수단이 없다는 것이 이미 측정으로 확인됐다.**

## 1. 촬영 전 코드 준비 — **완료**

### 1-1. 프레임 그룹키 규칙 추가 — ✅ 완료

`resplit_dataset.group_key()`는 AIHub(`^20210514_HHMMSS`)만 촬영 세션으로 묶고,
**그 외 파일명은 1파일 = 1그룹**으로 본다. 영상에서 뽑은 프레임에 이 규칙을 그대로
적용하면 **거의 같은 장면이 train/val/test에 흩어진다** — AIHub에서 실측 누수율
**99.7%**를 만들었던 바로 그 경로다(§1 표 #2).

확인한 현재 동작:

```
in_20260920_143000_f0001.jpg  ->  rf_in_20260920_143000_f0001   # 각자 다른 그룹 ✗
in_20260920_143000_f0002.jpg  ->  rf_in_20260920_143000_f0002
```

**적용됨**: `_CLIP_FRAME`(`_f` + 숫자 4자리 이상)을 인식해 클립 단위로 묶는다.

```
tr_lab_20260920_007_f000180.jpg  ->  clip_tr_lab_20260920_007
tr_lab_20260920_007_f000600.jpg  ->  clip_tr_lab_20260920_007   (같은 그룹)
tr_lab_20260920_008_f000010.jpg  ->  clip_tr_lab_20260920_008   (다른 그룹)
```

기존 파일과 충돌하지 않음을 **실측으로 확인**했다 — `datasets/v1/train`·`v2/train`
21,631장 중 `_f<숫자>` 형태가 **0건**이다. 회귀 테스트도 그 사실을 고정한다.

자체 촬영본은 **층(stratum)도 따로 잡는다**(`clip_tr` / `clip_ev`). 기존 소스(실외·
AIHub)와 같은 층에 섞으면 실내 프레임이 val/test에 거의 안 들어가 실내 지표가 둔감해진다.

### 1-2. Pi raw 녹화 — ✅ 완료

`ClipRecorder`가 저장하는 프레임은 `MJPEGServer.push()`가 받는 **탐지 박스·ROI
오버레이가 이미 그려진 최종 프레임**이다(CLAUDE.md "영상 녹화" 절에 명시). 그대로
학습에 넣으면 모델이 **그려진 박스를 단서로 배우는** 오염이 생긴다.

**(a) raw 녹화 모드**를 구현했다. 기존 설치의 녹화 동작은 그대로다(기본 False).

```bash
# 학습용 촬영 — 오버레이 없는 원본이 저장된다
curl -X POST "http://<Pi>:8080/recording/start?raw=1"
curl -X POST "http://<Pi>:8080/recording/stop"
```

- 클립 사이드카(`.json`)에 `"raw": true`가 남는다 — 파일만 보고는 학습에 쓸 수 있는
  클립인지 알 수 없기 때문이다
- **복사 비용은 raw 녹화 중에만 낸다**(`ClipRecorder.wants_raw`). 1080p 한 장 복사가
  Pi에서 1~2ms라 평상시에 낼 이유가 없다
- 화면·스트리밍은 **항상 오버레이본**이다 — 운영 화면에서 탐지 결과가 사라지면 안 된다

(a)를 권한다. 기존 미해결 항목("Pi 카메라 프레임 자체의 도메인 갭")까지 같이 닫힌다.

## 2. 절대 지켜야 할 규칙

1. **학습용과 평가용은 촬영 세션 자체를 분리한다.**
   같은 클립에서 일부는 학습, 일부는 평가로 나누면 안 된다. **다른 날 · 다른 옷 ·
   가능하면 다른 사람**으로 찍는다. 프레임만 나누면 §1-1의 누수가 그대로 재발한다.
2. **`test2.mp4` · `test3.mp4` · `test4.mp4`는 학습에 절대 넣지 않는다.**
   이미 평가 기준으로 쓰고 있어, 학습에 들어가는 순간 지금까지의 모든 판정이 무효가 된다.
3. **카메라 위치·높이·각도는 실제 설치 위치와 같게 한다.** 도메인 갭을 닫는 촬영인데
   조건이 다르면 의미가 없다. 삼각대 위치를 바닥에 테이프로 표시해 두고, 학습 세션과
   평가 세션에서 같은 자리를 쓴다.
4. **촬영 중 카메라를 움직이지 않는다.** 한 클립 = 한 고정 시점. 각도를 바꾸려면
   녹화를 끊고 새 클립으로 시작한다(클립이 그룹 단위이므로).

## 3. 파일명 규칙

```
<용도>_<장소>_<YYYYMMDD>_<클립번호 3자리>.mp4      # 클립(원본 영상)
<용도>_<장소>_<YYYYMMDD>_<클립번호>_f<프레임 6자리>.jpg   # 추출 프레임
```

- `<용도>` : `tr`(학습) / `ev`(평가) — **이 접두사로 두 용도가 절대 섞이지 않게 한다**
- `<장소>` : `lab`, `hall` 등 짧은 식별자
- 예: `tr_lab_20260920_007.mp4` → `tr_lab_20260920_007_f000180.jpg`

**클립 번호까지가 그룹키**가 된다(§1-1). 프레임 번호는 그룹 안에서만 구분한다.

## 4. 촬영 목록

각 클립 **20~40초**. 한 클립에 한 가지 조건만 담는다(조건이 섞이면 나중에 무엇이
효과를 냈는지 가릴 수 없다).

### 4-A. 학습용 — 자세 (가장 중요)

§12-3에서 확인한 치우침(수직 15.6%)을 메우는 것이 핵심이다.

| # | 장면 | 클립 수 |
|---|---|---|
| A1 | 지팡이를 **몸에 붙여 수직으로** 들고 서 있기 / 좌우로 조금씩 움직이기 | 4 |
| A2 | 지팡이를 수직으로 든 채 **천천히 걷기** | 4 |
| A3 | 평소처럼 **앞으로 뻗어 짚으며 걷기** (기존 분포 보강) | 3 |
| A4 | 지팡이를 **접거나 바꿔 쥐는 동작** (좌↔우손 전환 포함) | 2 |
| A5 | 지팡이를 **몸 뒤/옆으로** 늘어뜨리고 이동 | 2 |

> A4는 §11-4에서 발견한 "가상 지팡이 박스가 반대쪽에 그려지는" 현상(test4에서 43%)의
> 원인 장면이기도 하다. 학습·평가 양쪽에 필요하다.

### 4-B. 학습용 — 방향·거리·조명

| # | 장면 | 클립 수 |
|---|---|---|
| B1 | 카메라 **정면으로 접근** → 통과 | 3 |
| B2 | 화면 **좌→우**, **우→좌** 횡단 | 각 2 |
| B3 | **먼 거리**(화면에서 작게) 통과 | 2 |
| B4 | **조명 변화** — 형광등 일부 소등 / 커튼 개폐 / 야간 | 3 |

### 4-C. 다인 (검증이 막혀 있는 두 과제를 여는 장면)

| # | 장면 | 클립 수 | 무엇을 여는가 |
|---|---|---|---|
| C1 | 지팡이 사용자 1명 + 일반 보행자 1~2명 동시 | 3 | §12-5 사람 단위 폴백 |
| C2 | 지팡이 사용자 **2명이 5~8초 간격**으로 같은 곳 통과 | 3 | §9 쿨다운 — 두 번째 사람 안내 |
| C3 | 두 사람이 **밀착해** 나란히 통과 (한 명만 지팡이) | 2 | §8-1 1:1 배정 |
| C4 | 일반 보행자만 여럿 (지팡이 없음) | 2 | 오탐지 측정 |

### 4-D. 네거티브

| # | 장면 | 클립 수 |
|---|---|---|
| D1 | **빈 장면** (사람 없음) — 시간대별 | 2 |
| D2 | **유사물**을 든 사람 — 우산, 등산스틱, 목발, 긴 막대, 청소도구 | 4 |

> D2는 "가늘고 긴 것 = 지팡이"만 배운 문제를 겨냥한다. 기존 유사물 네거티브와 같은
> 원칙으로 **유사물 자체에는 박스를 그리지 않고 사람만 라벨링한다.** 유사물에 박스를
> 그리면 그것을 지팡이로 가르치게 된다.

### 4-E. 평가용 (별도 세션 — §2-1)

| # | 장면 | 클립 수 | 비고 |
|---|---|---|---|
| E1 | 4-A ~ 4-C를 **축약 재현** | 6~8 | 학습 세션과 **다른 날/다른 옷/다른 사람** |
| E2 | 지팡이 사용자 2명 시차 통과 | 2 | 2단계 실영상 검증의 핵심 |

**평가 클립은 프레임을 뽑지 않는다.** 영상 그대로 `datasets/videos/`에 두고
`eval_video_recall.py`로 잰다.

**정답 구간을 촬영과 동시에 기록한다** — "지팡이가 화면에 보이는 시간(초)". 나중에
영상을 다시 보며 만들려면 몇 배로 힘들다. `datasets/videos/video_gt.json` 형식:

```json
"ev_lab_20260921_001.mp4": [[3, 11], [19, 26]]
```

## 5. 수량 산정

| 항목 | 값 | 근거 |
|---|---|---|
| 학습 클립 | **약 30개** (4-A~D 합계) | 위 표 |
| 총 촬영 시간 | 약 15분 | 30클립 × 30초 |
| 프레임 추출 | **2 fps** | 30 fps 전부 뽑으면 거의 같은 장면이 중복된다. 0.5초 간격이면 자세 변화가 보인다 |
| 추출 프레임 | **약 1,800장** | 15분 × 60 × 2 |
| 라벨링 대상 | 약 1,800장 | 지팡이 + 사람 |
| **예상 라벨링 시간** | **3~5시간** | 장당 6~10초 |

### 이 정도면 충분한가 — 정직한 답

**모른다. 한 번에 맞추려 하지 말 것.** 현재 학습셋의 지팡이 이미지가 6,678장이므로
1,800장은 약 21%가 된다. 실내가 **0장**이던 상태에서 21%면 큰 변화지만, 얼마나
올라갈지는 학습해 봐야 안다.

**그래서 1차로 1,800장을 넣고 재학습해 실내 탐지율을 재는 것까지를 한 사이클로 본다.**
부족하면 2차 촬영을 한다. 처음부터 5,000장을 찍으면 라벨링에 며칠이 들고, 그래도
부족할 수 있다.

- [ ] 촬영 중 카메라를 건드리지 않았는지 클립마다 확인
- [ ] 마지막에 **빈 장면(D1)**을 꼭 찍는다 — 잊기 쉽다

## 7. 반입 절차

```bash
# 1) 평가 클립은 영상 그대로 둔다
cp ev_*.mp4 datasets/videos/
#    video_gt.json에 정답 구간 추가

# 2) 학습 클립에서 2 fps로 프레임 추출 (파일명 규칙 §3 준수)
#    ffmpeg -i tr_lab_20260920_007.mp4 -vf fps=2 tr_lab_20260920_007_f%06d.jpg

# 3) 라벨링 → datasets/sources/indoor_<날짜>/{images,labels}

# 4) 그룹 단위 재분할 (★ §1-1의 group_key 변경이 끝난 뒤)
python tools/data/resplit_dataset.py ...

# 5) 누수 검사 — 이게 통과해야 학습을 시작한다
python -m pytest tests/test_resplit_dataset.py -v

# 6) 학습
yolo train cfg=configs/train_v12_indoor.yaml

# 7) 판정 — 기존 영상과 새 평가 영상 양쪽에서
python tools/eval/eval_video_recall.py --video datasets/videos/test1.mp4 ...   # 회귀 확인
python tools/eval/eval_video_recall.py --video datasets/videos/ev_lab_*.mp4 ... # 개선 확인
```

**증강 설정은 `degrees=0`, `multi_scale=0`을 유지한다**(§3-1). 자세 다양성은 회전
증강이 아니라 **실제 촬영**으로 채우는 것이 이 계획의 전제다.

## 8. 촬영 후 판정 기준

| 지표 | 현재 | 목표 |
|---|---|---|
| 실내 탐지율 (conf 0.55) | 2.8% (test4) | **≥ 40%** |
| 실외 탐지율 (test1) | 75.8% | **유지** — 떨어지면 실내 데이터가 실외를 밀어낸 것 |
| 정지 이미지 mAP50 | 0.947 | 유지 (split이 바뀌므로 **같은 split끼리만** 비교) |
| 다인 영상 안내 횟수 | 측정 불가 | **측정 가능해질 것** |

> **1차 기준은 실영상 지표다**(§2). 정지 이미지 mAP가 올라도 실영상이 안 오르면
> 채택하지 않는다 — §4-0에서 정지 이미지 1위(yolo11n)가 배포 최하위였던 사례가 있다.
