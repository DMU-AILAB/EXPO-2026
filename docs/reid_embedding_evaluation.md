# 사람 재식별(Re-ID) 임베딩 평가 — 중복 집계·카메라 간 동일인 인식의 전제 조사

**목적.** 같은 사람이 가려졌다 다시 잡히거나 다른 카메라로 넘어가도 한 명으로 세려면 **위치가 아니라 외형**으로
"같은 사람인가"를 판정해야 한다. 이 문서는 그 판정에 쓸 수 있는 외형 특징이 얼마나 구분하는지,
Pi 4에서 감당할 수 있는지를 잰다. **구현 결정이 아니라 판단 근거다.**

> 요약: 색 히스토그램(AUC 0.75~0.84)은 합치는 근거로 부족했다. 학습된 임베딩은 **OSNet x1.0급이 AUC 0.90**
> (혼잡한 `1.mp4` 제외 0.95)으로 확실히 낫지만, 가장 작은 모델(Pi에서 약 7 ms)은 색 히스토그램보다 조금 나은
> 0.85다. **오합침 1%를 요구하면 같은 사람을 27~46%밖에 못 잇는다.** 안내 판정에 쓰기에는 아직 이르고,
> **통계 중복 제거용(보수적 임계값)** 으로는 검토할 만하다.

## 1. 측정 방법

- **크롭 4,847장** — `datasets/videos/` 23편을 6 fps로 샘플링, yolov8l(conf 0.4) 사람 탐지 + `SimpleTracker`
  트랙 id. 크롭은 128×256으로 맞췄다(`tools/eval/cache_person_crops.py`).
- **양성 쌍**(같은 사람 근사) — 같은 트랙의 1초 이상 떨어진 두 시점. **음성 쌍**(다른 사람) — 한 프레임에
  동시에 보이는 서로 다른 트랙. 음성이 같은 장면·같은 조명이라 쉽지 않은 쌍이다.
- **정답 잡음.** 트랙 id는 `SimpleTracker`가 붙인 것이라 혼잡한 장면에서 신원이 바뀐 구간이 양성에 섞인다.
  모든 후보에 똑같이 불리하게 작용하므로 비교는 공정하지만 **절대 수치는 낮게 나온다.** 그래서 혼잡한
  `1.mp4`(동시 6명, 트랙 33개)를 뺀 값을 함께 적는다.
- **지표** — AUC(양성 거리 < 음성 거리일 확률)와, 서로 다른 사람을 한 명으로 잘못 합치는 비율(오합침)을
  1%/5%로 묶었을 때 같은 사람을 이어 주는 비율. 임계값은 음성 분포의 1%/5% 분위수.
- **지연** — 1 스레드, 배치 1. PC와 Pi 4 모두 같은 ONNX로 재서 비율을 얻었다(아래 §3).

## 2. 구분력

| 후보 | 크기 | 차원 | AUC (전체 / 1.mp4 제외) | 오합침 1% → 같은 사람 통과 | 오합침 5% → 같은 사람 통과 |
|---|---|---|---|---|---|
| 색 히스토그램(상·하체 HSV 8×4×4) | — | 256 | 0.78 / 0.83 | — | 0.39 / 0.56 |
| OSNet x0.25 (MSMT17, ONNX) | 0.9 MB | 512 | 0.848 / 0.892 | 0.13 / 0.18 | 0.44 / 0.56 |
| OpenVINO `person-reidentification-retail-0288` (x0.25급) | 0.36 MB | 256 | 0.849 / 0.900 | 0.30 / 0.41 | 0.52 / 0.67 |
| OpenVINO `…-0287` (x0.5급) | 1.2 MB | 256 | 0.867 / 0.914 | 0.30 / 0.43 | 0.60 / 0.76 |
| OpenVINO `…-0277` (x1.0급) | 4.2 MB | 256 | **0.902 / 0.950** | 0.27 / 0.46 | 0.64 / 0.82 |

(통과율은 `전체 / 1.mp4 제외`. 색 히스토그램은 1% 지점을 재지 않았다.)

해석:

- 모델이 클수록 구분력이 오르지만 **작은 모델은 색 히스토그램과 큰 차이가 없다**(0.85 vs 0.78~0.83).
  Pi에서 현실적인 크기(x0.25)에서는 이득이 작다.
- 오합침 1%를 요구하면 어떤 모델도 같은 사람의 절반도 못 잇는다. 즉 **"이어 주는 쪽을 보수적으로"** 쓰면
  많이 놓치고, 느슨하게 쓰면 다른 사람을 합친다.
- `1.mp4`(혼잡)를 빼면 전 모델이 0.04~0.05 오른다. 정답 잡음의 영향이 이만큼 크다는 뜻이기도 하다.

## 3. Pi 4 지연

| 모델 | PC 1스레드 | Pi 4 1스레드 |
|---|---|---|
| OSNet x0.25 (ONNX Runtime) | 11.5 ms | **33 ms 실측** (2스레드 21 ms) |
| OpenVINO 0288 | 2.4 ms | 약 7 ms *(추정)* |
| OpenVINO 0287 | 6.4 ms | 약 19 ms *(추정)* |
| OpenVINO 0277 | 19.8 ms | 약 57 ms *(추정)* |

- 실측은 **운영 중인 기기에서** (`visionguide-device`가 돌고 부하 1.9~2.6일 때) 쟀다 — 탐지와 같이 도는 조건이다.
- 추정치는 OSNet ONNX의 Pi/PC 비(2.9배)를 OpenVINO 수치에 그대로 곱한 것이다. Pi에서 OpenVINO를 돌려
  확인하지 않았고, 실제 Pi 런타임은 TFLite라 변환 후 INT8 속도는 따로 잴 것.
- 임베딩은 **프레임마다가 아니라 트랙 생성 시와 몇 초마다 한 번**만 뽑으면 된다. 사람이 3명이면 초당 몇 번,
  7~57 ms를 그 정도 쓰는 것이라 12.76 fps 탐지 루프 예산(약 78 ms/프레임)에 들어가지만, 0277급은 한 번에
  프레임 시간의 상당 부분을 쓰므로 별도 스레드가 필요하다.

## 4. 이 평가가 모르는 것

- **카메라 간 성능은 재지 못했다.** 평가 영상은 전부 한 시점이다. 카메라가 달라지면 시점·조명·해상도 차이로
  구분력이 이보다 **더 떨어진다**(일반적으로 재식별은 카메라 간에서 크게 나빠진다). 2대 카메라가 서로 다른
  장소를 보는 현장 영상이 있어야 한다.
- **정답이 트래커 id다.** 사람이 확인한 동일인 라벨이 아니다.
- **영상이 학습 분포 밖일 수 있다.** 가중치는 MSMT17/Market류 보행자 데이터로 학습됐고, 이 프로젝트의 CCTV
  시점·해상도와 다르다. 크롭 해상도가 낮은(원거리) 사람은 더 어렵다.

## 5. 가중치와 라이선스

- `anriha/osnet_x0_25_msmt17` (Hugging Face, MIT 표기) — **원본 가중치는 MSMT17로 학습**됐다. MSMT17은 연구용
  조건의 데이터셋이라 **상용 배치 전에 확인이 필요하다.**
- OpenVINO Open Model Zoo `person-reidentification-retail-0277/0287/0288`(Apache-2.0)은 Intel이 자체 데이터로 학습한
  것이다. FP16 IR로 받아 PC에서 OpenVINO로 돌렸다. Pi용으로 쓰려면 ONNX/TFLite 변환이 필요하며 검증하지 않았다.
- HF ONNX는 **배치가 16으로 고정**돼 있다. 입력·출력의 0번 차원을 `N`으로 바꾸면 배치 1에서 같은 값을
  낸다(확인함):

  ```python
  import onnx
  m = onnx.load("osnet_x0_25_msmt17.onnx")
  for io in list(m.graph.input) + list(m.graph.output):
      io.type.tensor_type.shape.dim[0].dim_param = "N"
  onnx.save(m, "osnet_x0_25_msmt17_dyn.onnx")
  ```

## 7. 결론과 다음 단계 제안

1. **지금 쓸 수 있는 것은 통계 중복 제거 한정이다.** 안내 쿨다운 같은 안전 판정에는 오합침 비용(지팡이 사용자
   안내 누락)이 커서 쓰지 않는다. 통계는 한 명을 두 번 세는 것과 두 명을 한 명으로 세는 것의 비용이 비슷하므로
   임계값을 오합침 1~5% 수준에 두는 것도 선택지다.
2. **채택 전에 필요한 것:** (a) 2대 카메라 현장 영상(최소 같은 사람이 양쪽에 나오는 구간)과 동일인 라벨,
   (b) 후보를 OpenVINO 0287/0277급과 OSNet x0.25로 좁힌 뒤 Pi에서 TFLite INT8로 변환한 속도·정확도 실측,
   (c) MSMT17 가중치의 배포 조건 확인.
3. **더 싸게 얻는 개선:** 한 장 임베딩 대신 트랙의 **여러 프레임 임베딩 평균**을 쓰면 구분력이 오른다(이번에는
   프레임 단위로 쟀다). 임베딩 + 위치/시간 제약(카메라 인접·이동 시간 창)을 합친 비용으로 매칭하면 외형 단독보다
   오합침이 크게 준다.
